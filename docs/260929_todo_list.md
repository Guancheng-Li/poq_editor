## 一、召唤修改崩溃 —— ✅ 已修复(2026-10-16), 待 1.30 版回归测试

> **状态更新(2026-10-16)**:根因是旧 0x53xxxxxx "绝对地址"实为 EasyRPG.dll 镜像内
> 固定偏移的快照(当年基址恰为 0x53740000),游戏开 DYNAMICBASE 后每次启动失效。
> 已全部改为 `基址 + kOff*`(9 目标逐个实测,见 `data/py/find_summon_addr.py`),
> 加入口自检(表 cnt + rec469 长名,过期即中止)、控制标志从原版 A1 指令运行时实测、
> scratch 6 级高地址。Steam 版真机验证:mon/soldier/assassin 三路径 + 游戏内召唤
> 刺客 + 全部 6 大类×子类表匹配扫描 + 槽还原逐字节 —— 全部通过。
> **遗留:用户回头在 1.30 版测一遍**(Summon130.cpp 本就是模块相对模型,预期无恙)。
> 以下为当时的排查记录(留档):

### 现象
用户报告：召唤修改会导致游戏崩溃。测的是 Steam 版。

### 已排除的原因
召唤命令本身**与 python 参考版逐字节一致**，逐项核对均无差异：

| 项 | python 参考 | imgui 移植 | 一致 |
|---|---|---|---|
| 补丁偏移 | `0x35BAA` / `0x3586D` / `0x35C32` / `0x3585F` / `0x6FAC6` | 相同 | ✓ |
| 补丁字节 | `83 3D CC 88 BB 53 7F`、`EB 20 90 90 90 90`… | 逐字节相同 | ✓ |
| 命令流程 | 冲突回退 → group → mon/刺客/秦兵分支 → 尾部补丁 | 相同 | ✓ |
| 秦兵表扫描 | `0x53bfab78 + 8 + i*0x140` | 相同 | ✓ |
| 备份/释放 | `%TEMP%/*.json`，restore 时释放 scratch | 相同 | ✓ |
| 基址解析/写入 | `EnumProcessModulesEx` / `WriteProcessMemory` | 相同 | ✓ |

召唤代码自 `23f6577`（"imgui版：支持召唤修改"）一次提交后再未改动。

唯一发现的逻辑分歧（**窄，暂未确认为崩溃主因**）：

- **python**（`data/py/summon_tool_steam.py::alloc_scratch`）：依次试 **6 个固定高地址**
  `0x70000000 → 0x60000000 → 0x50000000 → 0x40000000 → 0x30000000 → 0x20000000`，最后才 ANY 兜底。
  注释明确写：**「低位 VirtualAllocEx 会被游戏意外访问而崩溃」**。
- **imgui**（`SummonSteam.cpp::AllocScratch`）：只从 `0x70000000` 向下扫 512 个 64KB 页
  （覆盖 `0x70000000~0x6E000000`），这个窗口全被占就**直接 ANY 兜底（低地址）**。
  → 行为不同，可能落到 python 明令警告会崩的低地址区。
  仅在**召唤秦兵 1/2/6 大类**（长名 >10B、需 scratch 标签）时生效。

### 真正的根因（后续发现，高置信度）

排查视野字段时顺带发现：**游戏开着 ASLR，硬编码的绝对地址每次启动都失效。**

2026-09-24 实测当前进程布局：

| 模块 | 无 ASLR 基址 | 本次实际基址 |
|---|---|---|
| `POQ.exe` | `0x00400000` | `0x008C0000` |
| `EasyRPG.dll` | `0x10000000` | `0x78110000` |

`POQ.exe` 的 `DllCharacteristics = 0x8140` → **DYNAMICBASE=on**，两个模块每次启动随机化。

召唤工具里这批**绝对地址在当前进程里根本读不到**（实测 `read(0x53b70450)` 直接失败）：

- 名字槽 `0x539771A4` / `0x539771B0`(朱厌) / `0x539771BC`(善翼)
- 刺客记录 `0x53C1F5C0`(弓) / `0x53C1F700`(刀)
- 秦兵类型表 `0x53bfab78`，空指针哨兵 `0x53bfa410`
- 属性 hash 表 `0x53b70450`
- 补丁点里引用的绝对地址 `0x53bb88cc`、`0x53775C32/34/54`

这些地址**既不在 EasyRPG.dll 映像内**（`0x53B70450 - 0x10000000 = 0x43B70450`，远超 `SizeOfImage = 0x81A000`），
**也不在 POQ.exe 映像内**（`0x53B70450 - 0x400000 = 0x537B0450` > `SizeOfImage = 0x5F7000`）
→ 它们是**运行时堆/自建分配**的地址，**必然随启动变化**。

写进这些地址 = 写到无关内存 = 崩游戏。

> **反例（不受影响）**：人物修改 tab 一直稳定，因为它用 **模块基址 + 偏移**
> （`EasyRPG.dll + 0x4797FC` → EDI → `+0x28` = 角色结构体），天然免疫 ASLR。

### 修法（方案已定，未实施）

把绝对地址改成**运行时动态定位**。注意：这些地址不在任何模块映像内，
所以**不能简单转成 DLL 相对偏移**，必须真搜索：

| 目标 | 定位方法 | 状态 |
|---|---|---|
| 名字槽（召唤兽朱厌/善翼/狍鸮） | 按 GBK 串在可写内存里搜 | 未实施 |
| 属性 hash 表 | 用已知合法属性名（`Level`/`Money`/`Friend`/`G_AIGroup`…）做约束扫描。约束：各字符块相 AND 恰好剩 1 bit；块 = `T + char_hash(c) + pos*0x800` | 脚本已写（`data/py/find_attr_tab2.py`），**未跑出结果** |
| 刺客记录、秦兵表 | 按结构特征/已知子串反查 | 未实施 |

已写好的脚本：
- `data/py/find_attr_tab.py` —— 扫 DLL 映像（**已确认表不在映像内，此路不通**）
- `data/py/find_attr_tab2.py` —— 扫进程可写内存（写完未跑通，`iter_regions` 是生成器、`len()` 报错未修）

**验证方式**：修复后进游戏点激活 → 看工具输出日志里每个补丁的 `[OK]`/`[!!]` 与字节对比
→ 进游戏按召唤键 → 确认不崩且召唤出目标怪。

## 二、P2 内存读取批量化 —— ✅ 已验证(2026-10-16)

> **状态更新(2026-10-16, Steam 真机)**:道具修改「读取属性」(19 词条物品)与
> 「复制上一件物品」实测:词条列表与游戏内显示完全一致(值/颜色/激活),写入条数正确。
> 读取速度感知无差异 —— 符合预期(P2 优化的是系统调用次数,该量级本就不是肉眼瓶颈)。
> 以下为原始背景(留档):
属 `docs/260919_optimization_plan.md` 的 P2 项：**读游戏内存时每个 4 字节一次系统调用 + 一次堆分配**。

原实现（`Native/ProcessMemory.cpp::ReadUInt32`）：
每次调 `Read()` → 一次 `ReadProcessMemory` **系统调用** + 返回**按值 `vector`**（堆分配）。
`GameModder::ReadAttributes` 每节点读 5 个字段 = 5 次调用；20 条词条的武器 ≈ 120 次系统调用。

### 已完成的改动
- `ProcessMemory::ReadBuf(addr, out, size)` —— 读进调用方缓冲、**零分配**、失败返 `false` 不抛异常
- `ReadNodeAddrs` —— 用 `ReadBuf` 读 next
- `ReadAttributes` —— 节点字段全在同一槽内（`id 0x0C` … `value 0x20`），
  改为**整段一次读**（按配置算出 `need`，循环外分配一次缓冲、逐节点复用）

### 待办：游戏内验证（**离线测不到，必须进游戏**）
1. 点「读取属性」→ 词条列表应与改动前完全一致（值/颜色/激活/类型）
2. 点「复制上一件物品」→ 写入条数与提示一致
3. 观察「读取属性」的响应速度（预期明显变快）

## 四、视野字段 —— ✅ 已解锁(2026-10-17 E1/E2/E3 实测)

### 定位结果
**角色结构体 `+0x198` = 视野**（2026-09-24 内存差分实测）：

装/卸"视野 +25"武器，19 处变化里**唯一差值 = +25** 的就是它：

```

```

同批变化里其余是那把武器的其它词条：

| 偏移 | 变化 | 对应词条 |
|---|---|---|
| +0x030 / +0x034 | +50 / +50 | 生命 / 生命上限 |
| +0x044 | +75 | **未命名** |
| +0x048 / +0x04C / +0x050 | +50 | 力量 / 体质 / 敏捷 |
| +0x064 / +0x068 | +18 | 普通攻击（min/max） |

| +0x188 | +35 | **未命名** |
| +0x0AC / +0x0B0 | +1507 / +1889 | 闪避率 / 命中率 |
| +0x430 | +10 | **未命名** |
| +0x0C0 / +0x0C4 | 反复变 | 坐标（噪声） |

交叉验证：孔刚（未装该武器）`+0x198 = -1`（未设置哨兵），与该结构体其它空字段风格一致。

### 实验结论(2026-10-17, E1/E2/E3 全部完成)
- 写 +0x198 **任意值均安全**(0/1/100/255/999/10000/65535 逐级实测, 每步 1/3/10s 存活检查),
  游戏保留写入值; 过期地址保存两轮测试也正常
- **游戏只在换图/进图时读取该值派生迷雾, 运行中不实时消费**(写 65535 迷雾无变化,
  换图后生效) —— 与装备词条"立即生效"是两条路径
- 当初"改视野必崩"系冤案: 最可能是当时(9月底)编辑器保存路径其它字段的写入缺陷
  (字符串无容量保护/失败静默), 已被 260929 加固(#4/#7/#10/#11)修掉
- 人物 tab 已加提示"视野改写换图/读档后生效"
